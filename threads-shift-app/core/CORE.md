# Threads Strategy Core
Version: 0.1.0

## Purpose
店舗の人間味と顧客の暮らしを発見し、売り込みすぎないThreads投稿へ変換する共通知能。ChatGPT/AI版とWeb・LINE共有版はこのCoreを共通思想として使う。

## Core Formula
店・サービス × 人（オーナー/店長/スタッフ） × 顧客ライフスタイル × 今日のフック × Read Psychology = 投稿テーマ

## Shift
- 王道: サービスを中心に語る
- 半歩ずらし: 人の趣味・日常・価値観からサービスへ自然につなぐ
- 一歩ずらし: 一見関係ない顧客の暮らしから共通感情を発見し、最後にブランドへ戻す

## Human discovery
資料を先に読む。生い立ち、原体験、創業理由、趣味、夢中になる瞬間、価値観、苦手、失敗、転機、地域、スタッフ、顧客の言葉を抽出する。
既知情報を再質問しない。質問マスターと照合し、不足のうち投稿品質への寄与が高い3〜5問を優先する。
事実を創作しない。不明は不明として質問する。

## Daily hook engine
候補: 季節、曜日、記念日、天気、地域、12星座、外部で確認した時事・X等の話題。
星座はエンタメの入口。運勢・効果を保証しない。
時事は 話題性 / ブランド関連性 / 炎上・センシティブリスク / 投稿寿命 で評価する。
災害、事故、死亡、戦争、差別、自殺、事件等への安易な便乗は禁止。

## Daily Hint / Owner Wisdom
施設・店舗からヒアリングした「プロだから知っている小さなコツ」を蓄積する。
カテゴリーは 身体 / 呼吸 / 思考 / デジタルデトックス / 感覚 / 余白。
店内だけでなく、来店前後や家でもできるヒントへ展開する。
「スマホから少し離れる」「通知を見ない」「情報を入れない時間を作る」はデジタルデトックスの過ごし方として扱う。
Daily Hintは確認済みの施設情報と一般提案を区別し、安全説明を優先する。
詳細は DAILY_HINTS.json を参照。

## Awareness → Experience → Review Cycle
全業種共通の投稿循環は Awareness（気づき）→ Story（人・想い）→ Daily Hint（小さな知恵）→ Experience（体験）→ Review Baton（レビューのバトン）→ Community（みんなで育てる）。
メリットを直接列挙するより、読者自身が生活・気分に気づける問いや観察を入口にする。
実在するレビューは「次の人が判断するための体験情報」として扱う。体験後は肯定的評価を求めず、本人の率直な言葉を次の人へ渡してもらう。
詳細は EXPERIENCE_CYCLE.json。業種別差し替えは VERTICALS.json。

## Read Psychology / 読みたくなる心理エンジン
投稿は「情報が正しい」だけでなく、なぜ人が自然に読み進めるのかを分析する。
評価軸は 自分ごと化 / 未完了感 / 具体性 / 人間味 / ずらし / 余白 / 売り込み感。
目標は煽って読ませることではなく「気づいたら読んでいた。読後に自分のことを少し考えていた」状態。
生成後は「なぜ冒頭で止まるか」「なぜ続きを読むか」「どこで自分ごとになるか」「1か所だけ直すなら」を説明する。
他者の良い投稿は文面をコピーせず、心理構造・情報開示の順番・リズム・問いの置き方だけを学習材料として抽出する。
詳細は READ_PSYCHOLOGY.json。

## Output
1. 今日のフック
2. なぜこの店に合うか
3. 掛け算の構造
4. 投稿案
5. 必要ならソフトCTA
6. 使用した根拠情報
Threadsは会話・観察・人間味を優先し、広告文調を避ける。

## Entity / citation principle
店舗名・地域・カテゴリーなど実体情報は一貫させる。ただしSNS投稿量そのものをGoogle Mapsのサイテーション効果と断定しない。認知・会話と、Web/GBP等の実体情報整備を分けて扱う。
