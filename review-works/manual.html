Review Works Evolve
使い方マニュアル

実体験レビューの作成、店舗返信支援、Ask Mapsを意識した意味情報分析、医療・景表法の注意点、自己分析の読み方までをまとめています。

01 / START

最初に

Review Worksは「キーワードを詰め込むツール」ではありません。実際の体験に含まれる具体情報を整理し、利用者に役立つレビューや誠実な店舗返信を作るための支援アプリです。

基本原則
事実 → 感情 → 役立つ情報。分からないことは補わず、未確認情報は断定しません。
02 / CREATE

レビューを作る

店名・エリア・業態を入力します。
体験メモをそのまま入力します。注文、味、店内、接客、待ち時間、アクセス、支払いなどです。
「体験を分析してレビュー案を作る」を押します。
生成文が実体験と一致しているか確認してから投稿します。
精度を上げるコツ
「良かった」だけより、「平日13時、注文後約8分で提供」のような一次情報が役立ちます。覚えていない数字は作らないでください。
03 / SELF AUDIT

自己分析の見方

具体性・有用性・一次情報性・Ask Maps対応力・自然さ・安全性を見ます。100点を目指す必要はありません。実際に確認した2〜4軸が自然です。

04 / REPLY

レビュー返信を作る

店名・業種・星評価を選び、レビュー全文を貼ります。
店舗側で確認できる事実があれば入力します。個人情報は入れません。
「心理仮説と返信案を作る」を押します。

表示される「心理」は感情・期待・不満の背景・再来店障壁の仮説です。人格や本心を断定しません。

05 / ASK MAPS

意味情報

順位操作用のキーワードではなく、待ち時間・駐車場・静かさ・アクセス・設備など「質問に答えられる具体情報」を意味軸として扱います。返信には原則1〜2軸だけ自然に使います。

06 / MEDICAL

クリニック・歯科

公開返信で避けること
治療効果の保証／「絶対」「必ず治る」等の誇大表現／他院より優れているとの比較／患者本人の症状・診断・処方・治療内容の確認や開示／患者の治療効果に関する体験談の広告的再利用。

自動チェックは法的助言ではありません。重要案件は責任者確認をしてください。

07 / UPDATE

最新情報の更新

公開版は起動時に data/knowledge.json を読みます。知識ファイルを更新すれば、利用者へHTMLを再配布しなくても次回アクセス時に反映されます。

変更検知 → 内容確認 → knowledge.jsonへ反映、の3段階で安全に更新します。
08 / SHARE

他の人に渡す

GitHub Pages公開後はURLだけ送れば使えます。対応ブラウザではホーム画面へ追加してアプリのように使えます。
